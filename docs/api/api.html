API reference¶

HTTP client for the Biblissima portal’s RQL endpoint.

The portal is a CubicWeb application. Its /view URL accepts an RQL query (rql=) and a view name (vid=); the jsonexport view returns rows as JSON arrays. Two behaviours matter in practice:

  • an invalid RQL query returns HTTP 200 with an empty list, not an error;

  • very large responses can arrive truncated.

The client therefore refuses empty results unless the caller says an empty list is a legitimate answer, validates that the body is JSON (retrying if it is not), throttles requests, and can cache responses on disk.

Rights and credits for IIIF manifests, from Biblissima’s own data.

Each manifest statement (property P196) on a manuscript’s Wikibase item carries a qualifier P191 naming the digital library that provides it. That library is itself an item, with an operator (P200), optionally a licence (P187) and a conditions-of-use URL (P366). This module follows that chain:

manuscript item –P196[P191]–> digital library –P200/P187/P366–> text

Rights are therefore stated per digital library, not per manifest, and only as completely as Biblissima records them: many libraries have no licence there, and those manifests get an empty manifest_license.

Read the CTS catalogue (__cts__.xml metadata files) of Perseus / OGL repos.

A Canonical Text Services (CTS) URN names a text hierarchically. At the work level it has the form urn:cts:<namespace>:<group>.<work>:, for example urn:cts:greekLit:tlg0363.tlg001:: five colon-separated components, the last (the passage) empty. The catalogue files omit the trailing colon, so work_urn() and group_urn() add it.

Map Wikidata items to CTS text groups via TLG and PHI author identifiers.

Wikidata records the Thesaurus Linguae Graecae author number (e.g. 0363 for Ptolemy) and the PHI Latin Texts author number. Those numbers are the group part of CTS URNs in the greekLit (tlg0363) and latinLit (phi0690) namespaces.

The mapping is read from a SPARQL JSON result saved beforehand, with variables ?p (the person), ?tlg and ?phi (the numbers); see SPARQL_QUERY. A result whose ?tlg or ?phi values are not plain digit strings is rejected.

biblissima.wikidata.SPARQL_QUERY = 'SELECT ?p ?tlg ?phi WHERE { { ?p wdt:P3576 ?tlg } UNION { ?p wdt:P6941 ?phi } }'¶

P3576 = TLG author ID, P6941 = PHI Latin Texts author ID. (Check numbers on Wikidata itself: other Wikibase sites number properties differently.)

Match Biblissima works to CTS works and build texts.cex.

There is no Biblissima-to-CTS mapping in the data, so matching is in two steps:

  1. Author. Each Biblissima work has authors (people credited as “Auteur du texte” on its texts). A person linked to Wikidata is mapped to a CTS text group through the TLG / PHI author numbers Wikidata records (biblissima.wikidata).

  2. Title. Within that group, the work’s titles (French, Latin…) are compared with the CTS work titles after folding case, accents and punctuation.

Only matches above threshold are written to texts.cex; weaker ones go to a review list.

Cross-index manuscripts and texts (textindex.cex).

The portal records which texts a manuscript contains as Manuscript has_part Component, Component related_text Text and Text work Work. A component sometimes nests inside another component (never deeper than two levels). A component’s minmax_folios attribute is a free-text folio range such as 176v-177* or 082-146*; it is often missing.

This module reads those links, keeps only manuscripts listed in mss.cex and works listed in texts.cex, and writes mss|text|location rows.

biblissima.textindex.normalize_location(raw: str | None) → str[source]¶

Tidy a folio range without inventing recto/verso information.

Whitespace and a trailing * are removed, en dashes and doubled hyphens become -, a f./ff. prefix is dropped (p. for pages is kept), and leading zeros are dropped from each end of a range (082-146 becomes 82-146). A range ending in a bare side, 32r-v, is written out as 32r-32v. Folio labels stay strings: 63bisr is left alone. A bare number stays bare, because the source does not say which side is meant. Lists (12-21v, 104-133v) and other free text are only tidied.

Alternative names for text groups and works (groupnames.cex, worknames.cex).

Biblissima keeps several name forms for a person (Person preferred_form and other_forms) and for a work (Work displayed_title, preferred_form and other_forms), each a Designation with a title. This module collects them for the works listed in texts.cex:

  • a work’s names go with the work’s CTS URN;

  • a person’s names go with the CTS group URN of the works they wrote, but only when Wikidata maps that person to the group’s TLG/PHI number, so that pseudonymous or wrongly attributed authors do not leak in.

Names that merely repeat the CTS name already in texts.cex are left out.

biblissima.names.clean_name(raw: str | None) → str[source]¶

Tidy one name form; return "" for forms that should be skipped.

Unicode is composed (NFC), whitespace collapsed and a trailing life-dates parenthesis ((0100?-0170?)) removed. A leading author statement such as Ptolemy, active 2nd century. Almagest is cut down to the title. Forms where several names were run together (... (dates)Other name) are skipped.

Assemble a composite data release file.

A release is one text file made of four blocks. Each block starts with a label line and runs to the next label line:

#!version

one data line: the contents of the version file (for example 2026a)

#!mss, #!texts, #!textindex

the full contents of mss.cex, texts.cex and textindex.cex, header line included

The file is written to <out dir>/<version>.cex.
